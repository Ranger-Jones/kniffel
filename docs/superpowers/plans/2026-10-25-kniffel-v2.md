# Kniffel v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mobile-Feinschliff, Ladezustände, anpassbare Emoji-Schnellwahl, optionaler Chat und Zeitlimit pro Zug.

**Architecture:** Einstellungen und Zugbeginn leben im bestehenden `games.state` (Engine bleibt die einzige Regelquelle, `now` wird injiziert). Chat bekommt eine eigene Tabelle mit RLS-Lesen + Realtime-INSERTs; geschrieben wird nur per Server Action. Schnellwahl als Spalte in `profiles`. UI-Arbeit nutzt bestehende Komponenten.

**Tech Stack:** wie v1 (Next 16, Supabase, Vitest, Playwright).

**Spec:** `docs/superpowers/specs/2026-10-25-kniffel-v2-design.md`

## Global Constraints

- Zeitlimits exakt: `null | 30 | 60 | 90 | 120` Sekunden; Standard `null`. Chat Standard an.
- Timeout-Regel: nicht gewürfelt → einmal würfeln; dann freies Feld mit max. Punkten, Gleichstand → erstes in `CATEGORIES`-Reihenfolge.
- Chat: 1–300 Zeichen (getrimmt), max. 1 Nachricht/Sekunde/Spieler, nur aktive Mitspieler, nur wenn `settings.chat`.
- Schnellwahl: genau 6 eindeutige Emojis aus `EMOJI_CATALOG` (60 Einträge); Standard `['🎉','😂','😱','🔥','👏','😭']`.
- Mobile: kein horizontaler Überlauf bei 360 und 390 px auf allen Seiten; Tippflächen ≥ 44 px.
- UI-Texte Deutsch, Sentence case.

## Review Focus

1. **Uhrenabweichung zwischen Client und Server** – Client meldet Timeout zu früh → Server lehnt ab, Client versucht es kurz später erneut, kein Fehler-Toast. → Engine-Test „zu früh“, Client-Wiederholung in Task 3.
2. **Mehrere Clients melden gleichzeitig Timeout** – nur einer wirkt. → Integrationstest in Task 2 (Zug-Token).
3. **Alte laufende Spiele ohne `settings`/`turnStartedAt`** – dürfen nicht abstürzen. → Engine-Test mit „Altzustand“ in Task 1.
4. **Chat-Spam / sehr lange Nachrichten / leere Nachrichten** – werden abgelehnt. → Integrationstests in Task 2.
5. **Lange Benutzernamen auf 360 px** – Teilnehmerliste/Kopfzeile laufen nicht über. → Overflow-Skript in Task 6 mit 20-Zeichen-Namen.

```sql
create table public.game_messages (
  id uuid primary key default gen_random_uuid(),
  game_id uuid not null references public.games (id) on delete cascade,
  user_id uuid not null references public.profiles (id) on delete cascade,
  body text not null check (char_length(body) between 1 and 300),
  created_at timestamptz not null default now()
);
create index game_messages_game_idx on public.game_messages (game_id, created_at);
alter table public.game_messages enable row level security;
create policy "Chat lesbar für Mitspieler" on public.game_messages for select to authenticated
  using (public.is_game_member(game_id));
alter publication supabase_realtime add table public.game_messages;
alter table public.profiles add column quick_emojis text[];
```
